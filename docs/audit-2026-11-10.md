# DrainTracer audit and work plan — 2026-11-10

Point-in-time audit against v5.6.0 plus the eight later commits on `main`. It
lists unfixed medium and low weaknesses in the opt-in agent and sharing
components; none is critical or high.

Coverage: engine, session/UI/CLI, reports, agent/sharing, CI, packaging, docs
and repository state. The P0 items were reproduced by the lead auditor; most P1
and P2 items are as reported by the per-cluster auditors with spot checks.

## 1. Verdict

Engineering hygiene is good: published wheel matches the manifest exactly, 402
doc links resolve, the HTML report renders cleanly with a strict CSP, the Linux
suite passes, and no critical or high security issue was found.

The core promise is the weak point. With default settings the detector:

- **fails a healthy process on one allocation.** A script that idles, allocates
  one 80 MiB block and idles again ends `memory CRITICAL`, `RESULT FAIL`, exit 1.
- **passes a real leak.** A script growing about 3.6 MiB/s with a GC-like
  sawtooth (private peak 232 MB in 60 s) ends `memory clear`, `RESULT PASS`, exit 0.
- **cannot see slow leaks.** A clean linear leak below about 0.22 MiB/s
  (0.77 GiB/h) raises nothing; below about 1.5 MiB/s (5.3 GiB/h) it never
  reaches HIGH, so the default `--fail-on high` exits 0.

Everything else ranks below that. The second theme is scope: v5.3.2 (26 Oct)
had 38 modules and 15.0k source lines; v5.6.0 (1 Nov) has 74 and 26.9k, with
420 commits on 31 Oct alone, zero-approval merges, and the roadmap's own gates
(T5, #31, #49) unmet. PyPI shows 2–30 downloads a day outside release days.

## 3. Work items in order

### P0-1. Fix detection (owner decision required; MINOR release)

`AGENTS.md` says to preserve the window and monotonic checks unless the design
is changed on purpose, so this needs your approval first.

Causes, all in `src/leak_detector.py`:

- `:1213` counts `curr >= prev`, so a flat series is "100% monotonic".
- `:1086-1087` takes delta from two endpoints; `:1255` scores it directly.
- `:1100`, `:1106`, `:1209-1226` judge adjacent raw samples, so noise or a
  sawtooth fails `MIN_MONOTONIC_RATIO` / `MAX_DROP_RATIO` at every window length.
- Nothing requires a verdict to persist, so the alert fires on the step sample.
- Default windows stop at 60 s, which sets the slow-leak floor above.

A candidate rule was prototyped outside the repo
(`detector_prototype.py`, path in section 5): bucket each window into 10 time
slices, use the low median per bucket, count only strict increases, require at
least 15% of the window's growth in both the early two-thirds and the last
third, and hold a verdict for 3 consecutive samples. On 18 synthetic scenarios
the current rule classified 9 as expected and the candidate 17. The candidate's
one miss is a staircase of +20 MiB every 15 s, so step handling needs more
thought (for example, count repeated steps across the longest window).

Steps:

1. Add permanent fixtures to `torture/`: single step then plateau, one-sample
   spike, sawtooth leak, noisy leak, staircase, slow leak. Add them to
   `verify_suite.py` with expected outcomes.
2. Add failing unit tests in `tests/test_leak_detector.py` for the same shapes.
3. Implement the bucketed evaluation as a pure function split out of
   `_evaluate_windows`; keep thresholds and the score formula unchanged at first.
4. Decide what `test_startup_growth_is_only_a_leak_without_warmup` (line 384)
   and the `startup-spike` torture case should now expect.
5. Address slow leaks separately: add longer default windows (5 and 15 min) or a
   session-long trend, then re-measure.
6. Rerun the calibration protocol on both platforms and replace
   `docs/calibration-results.md` with the new source-pinned results.

Done when: the two real scripts in section 5 give no failure and a HIGH
respectively, and every existing growth fixture still alerts.

### P0-2. Linux: a clock step loses the whole tree

psutil 7.2.2 computes `create_time()` as start ticks plus a live boot-time
read. `src/process_runner.py:99` and `:937-942` compare that epoch value, so a
wall-clock step makes every member look like a reused PID. Reproduced on WSL
with a real `sleep` and the boot-time read shifted 5 s: tracked set empty,
`terminate()` sent nothing, the process stayed alive. A paused tree would also
stay stopped.

1. On Linux, identify processes by field 22 (`starttime`) of
   `/proc/<pid>/stat`, parsed after the last `)`. Keep the epoch for display.
2. In `terminate()`, never clear state while `self._process.poll() is None`;
   fall back to `Popen.kill()` and `os.killpg`.
3. Use `time.monotonic()` for `_departed` expiry (`:709`).
4. Test in `tests/test_linux_processes.py`: shift `create_time()` by 2 s after
   identities are captured; the tracked set and resume list must not change.

### P0-3. Windows venv: phantom worker and red tests

In a Windows venv `sys.executable` is a launcher stub and the real interpreter
is its child. `src/process_runner.py:651` launches `.py` targets through it, so
the root is the stub and the interpreter shows up as a "new worker". The
documented API example (250 ms, 2 s window) on a script that only sleeps emits
`Handles leak signal MEDIUM … mostly new worker processes` in 6 of 6 venv runs
and 0 of 6 without a venv. Default 10 s windows are not affected.

1. In `_build_command`/`start`, when on Windows and `sys._base_executable`
   differs from `sys.executable`, launch the base executable with
   `__PYVENV_LAUNCHER__` set to `sys.executable` in the child environment. This
   is what stdlib `multiprocessing` does; verified here on 3.10, 3.12 and 3.14
   (one process, venv active, variable not inherited further).
2. Apply the same to `src/workload.py:117` and `src/preflight.py:171`.
3. `tests/test_checkpoints.py:102-126`: retry opening the store for up to 10 s
   after killing the writer instead of assuming the lock is free at once.
4. In `publish-pypi.yml`, make one `windows-current` leg create a venv under
   `$RUNNER_TEMP` and put its `Scripts` on `GITHUB_PATH` before installing, so
   job names (required checks) stay the same.

### P0-4. Survive termination and a closed stdout (PATCH)

Two ways a CI run loses its report, both reproduced on Windows:

- **Signals.** Only `KeyboardInterrupt` is handled (`src/headless.py:179`,
  `src/dashboard.py:207`, `src/main.py:782`), and targets are started in their
  own process group or session (`src/process_runner.py:371-374`). Ctrl+Break
  ended the monitor with `0xC000013A`: no RESULT line, no report, and the
  launched target still running. SIGTERM (CI cancel, `timeout`) and SIGHUP on
  Linux take the same path by reading.
- **Closed stdout.** Every event prints (`src/headless.py:309-311`), and the
  error handlers print again (`:182-183`, `src/main.py:993-994`). With the pipe
  closed, as in `draintracer --headless … | head -n 5`, the run exits 120 with
  no report.

Steps:

1. In `main()`, install SIGTERM and SIGHUP (POSIX) and SIGBREAK (Windows)
   handlers that raise a `KeyboardInterrupt` subclass so the existing cleanup
   and export run. Document the exit code.
2. Make headless output best-effort: catch `OSError` in `_print_line`, the
   summary and annotations, switch to a null sink, record one monitor error,
   still export and return `exit_status()`. Guard `_report_crash` the same way.
3. Tests in `tests/test_headless.py`: a subprocess run that receives
   `CTRL_BREAK_EVENT` or SIGTERM leaves a report and no surviving target; a
   console whose file raises `OSError` after N writes still exports.

### P1. Robustness and security (PATCH releases)

Engine:

- An unreadable helper that comes and goes clears the series forever
  (`leak_detector.py:652`); restart only when the same identity flips.
- A steady cadence above 2.0 s resets every window each sample (`:524-530`).
- An unexpected classifier exception fails every sample with no back-off
  (`:770-775`); one raw `OSError` from one member fails the sample
  (`process_runner.py:899-903`, `:928-932`).
- Retained snapshots cost about 500 bytes per process each: a 100-process tree
  reaches about 345 MiB in an hour (`history.py:66-72`, `session.py:109`).
- `pause()` aborts and resumes everything when a member exits mid-pause
  (`process_runner.py:523-527`).
- Launched descendants can escape on Windows; use a Job Object for every
  launch (`agent_jobs.JobProcess` already exists).

CLI, session and dashboard:

- `--headless --target ""` exits 1, the leak-verdict code, with a traceback
  (`src/main.py:829`, `:977-992`). Reject a blank target and build both front
  ends inside their `try`.
- Flags after a stray positional are silently forwarded to the target because
  of `nargs=REMAINDER` (`src/main.py:660-662`): `--target app.exe extra
  --fail-on low` leaves the gate at HIGH. Split argv at the first `--` and set
  `allow_abbrev=False`.
- A dashboard with no interactive input never ends after the target exits
  (`src/dashboard.py:187-191`); exit 2 or end on `tree_finished`.
- Exit codes disagree: a missing target is 1 in the dashboard and 2 headless;
  Ctrl+C is 0 inside the live loop and 130 elsewhere; over-budget is 5 headless
  and 4 in `diff` (`src/dashboard.py:171`, `:220`).
- Git repair (`src/main.py:88-122`): `git` is found by name, so a `git.exe` in
  the working directory can run; inherited `GIT_DIR` redirects it to another
  repository; the 60 s timeout does not bound grandchildren; and
  `pull --ff-only origin main` fast-forwards whatever branch is checked out.
  Restore from HEAD first and pull only on `main`. Two existing tests pin
  today's behaviour, so this needs your decision.
- A discovered `.drainrc` can set `checkpoint` and `report_dir` to absolute,
  UNC or parent-escaping paths (`src/config.py:325`, `:330`); `--quiet` hides
  which file was applied.
- Top-level settings are dropped silently when a `[draintracer]` table also
  exists (`src/config.py:235-240`).
- Checkpoints: a second session on the same path prints `Permission denied`
  plus an administrator hint (`src/checkpoints.py:150`, `src/session.py:463-467`);
  shutdown writes no final checkpoint; `.lock` files are never removed.
- `FORCE_COLOR` or `TTY_COMPATIBLE=1` makes redirected output count as a
  terminal, so the PyPI check runs although `PRIVACY.md` says it does not
  (`src/main.py:367`).
- `doctor` reports READY for flag combinations the real command rejects
  (`src/preflight.py:263` skips `src/main.py:815-834`).
- A failing lazy panel freezes the dashboard frame with no notice
  (`src/dashboard.py:231-234`).
- `K` on an attached tree is recorded as `exited` with zero kill attempts
  (`src/dashboard.py:353-354`, `src/session.py:953-954`).
- Windows picker: `à` is untypable and swallows the next key
  (`src/picker_input.py:90-93`).
- The `--config .\examples\drainrc.toml` example writes HTML under
  `examples/leak_reports/`, which `.gitignore` does not cover.

Agent, sharing, API:

- A handshake frame with a non-ASCII `proof` raises `TypeError` out of the
  serve loop and ends the agent (`agent_transport.py:501`, `agent_command.py:67`).
  Validate `[0-9a-f]{64}` first and catch per connection.
- The agent CLI prints `may_have_run: false` after the request was sent, and
  `--request-timeout` applies per transfer step (`agent_command.py:239-241`,
  `agent_transport.py:416`). Use one deadline and add `--request-id`.
- A script that starts an API session and exits without `close()` leaves the
  target running (`api.py:346`); add an `atexit` cleanup.
- The lowest role can push security events out of the audit trail
  (`team_store.py:192-198`); reserve quota for them.
- The listener buffers up to 16 MiB before authenticating
  (`team_transport.py:19`, `:235-236`); authenticate from a bounded prefix.
- Refuse `serve` from an elevated token unless explicitly allowed
  (`agent_transport.py:153`).
- The store's identity is the hash of the schema text with no migration path
  (`team_database.py:70`).
- The test certificate is a CA valid to 2036; reissue it as a leaf.

Reports and workloads:

- `redact_text` is quadratic: an 8 KiB line takes 1.9 s (`experiment.py:46-63`).
- Redaction misses `{"password": "…"}`, `PGPASSWORD=`, `clientSecret=`,
  `accessToken=`, `secret_key=`, `Authorization: token …` and token-only URLs.
- One overlong line stops log capture for the rest of the run
  (`workload_logs.py:83`, `:91-95`).
- `draintracer-report redact` crashes on a report `validate` accepts
  (`"markers": [null]`, `privacy.py:257`).
- `diff` and headless print report or process text with raw escape sequences
  (`diff_command.py:551-552`, `headless.py:317-324`).
- Strict diffs and baselines do not compare DrainTracer versions
  (`report_diff.py:659-667`).
- Pairwise and grouped drift rules disagree near the noise floor
  (`report_diff.py:461-464`, `repeat_comparison.py:147-150`).
- Open issues #131, #132, #134, #137 and #139 are all still real.
